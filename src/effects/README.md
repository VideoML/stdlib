# Frame effect lifecycle

Use `createEffectRegistry()` from `@videoml/stdlib/effects` to register trusted, shipped descriptors and factories. A registration provides a synchronous parameter validator in addition to the descriptor's JSON Schema; both must accept the input. The registry compiles the descriptor with Ajv 2020-12 and does not load remote schemas. Effect parameters are data, not executable schema code. Registered schemas must be trusted and self-contained. Each factory returns `mount`, asynchronous `seek`, and `dispose`. Its `seek` must resolve only after its own canvas, WebGL, assets and DOM work is settled. Calls are serialized per instance; callers must not mutate the same instance outside its controller.

`mountEffect(root, registry, config, context)` validates identity, version, parameters, frame interval and mount context. The controller `seek(frame)` uses absolute nonnegative composition frames and the configured `[startFrame,endFrame)` interval; it waits for the instance and document fonts/images. `dispose()` prevents new work, invokes an optional synchronous `cancel()` hook to reject pending operations, and calls effect cleanup once after pending work settles. Effects with cancellable asynchronous work must implement `cancel()` so disposal cannot wait indefinitely on them. `pause()` is a no-op for this explicitly sought controller; effects must not run an ambient clock. A failed mount remains terminal and automatically disposes partial resources, even if no seek or dispose follows. Assets are already resolved by the caller and passed through unchanged.

Player consumers use `mountPlayerEffect` from `@videoml/player`; renderer browser bundles use `mountRendererEffect` from `@videoml/renderer/effects`. Both delegate to this same lifecycle and registry. Renderer users of the effects entrypoint must install `@videoml/stdlib`; it is an optional renderer peer because existing renderer-only entrypoints do not need it. Existing player users can keep `mountVmlPlayer`, which returns its cleanup function; `createVmlPlayerController` separately exposes seek, pause and dispose. Explicit seek stops the timeline and serializes requests; an optional `settleFrame(frame, root)` hook must await asynchronous trusted visual handlers. A sync group shares a timeline and one seek queue: pause or seek from one member affects all members, and each group seek awaits every active member’s settlement hook, fonts and images before it resolves. Disposal unregisters that member; a disposed initiator’s pending seek rejects while other group members can continue.

For still capture, create a trusted, self-contained local browser bundle exposing `window.mountVideoMLEffect(root, config, context)` that calls `mountRendererEffect` with the same registry and effect implementation. `captureEffectFrames` from `@videoml/renderer/effect-capture` loads that bundle locally, mounts once, awaits each frame seek, captures PNGs and disposes. Existing ComposableRenderer scripts are unchanged and do not automatically parse these effect IDs. React components expecting the renderer context can be wrapped with `createReactEffect` from `@videoml/renderer/effects`; it renders the same component and cleans up its React root. By default it supports synchronous React/frame effects only. Components doing asynchronous drawing or asset work MUST supply `settleFrame(frame, root): Promise<void>` and resolve it only when the requested frame is ready; the adapter then awaits fonts and images.

`mountEffect` supplies a fresh frozen `context.timing` with the validated placement's `startFrame` and `endFrame`; it also copies those bounds for visibility. Mutation of the caller's configuration cannot change either. The field is optional in the TypeScript mount context for compatibility with direct mounts. New placement-relative effects must reject direct mounts without it with `EFFECT_TIMING_UNAVAILABLE`. For a pure timeline adapter, calculate local seconds as `(absoluteFrame - timing.startFrame) / fps` and clamp to the authored endpoints. Do not alter absolute seek or retime existing version 1 effects. XML start and end seconds retain `floor(start * fps)` and `ceil(end * fps)` respectively.

Renderer culling for `FrameEffect` uses the same rounded half-open frame interval as the player. This corrects fractional leading and trailing boundaries that were previously culled by exact seconds; existing integer-boundary frames and version 1 interpolation are unchanged. Other component timing retains its existing behavior.

The DOM fallback registry reserves `frame-effect` for this lifecycle: it must not insert an unknown-component placeholder into an effect host, where it would shift the canvas. Unknown non-effect components retain their fallback behavior.

Effects may declare `sceneInputs` as data-only pairs naming their `sourceSceneId` and `sourceFrame` parameter keys. Both values absent mean an alternate input such as an image asset; a partial or invalid pair fails. `context.sceneSnapshots` is an optional trusted native-pixel provider. It returns an owned `{bitmap, close()}` handle; effects must keep the handle open while their one derived canvas copy remains live, and close it when that copy is discarded or on cancellation. Missing providers fail `SCENE_CAPTURE_UNAVAILABLE`. The shared capture helper applies the request deadline, validates dimensions, and closes late handles. No DOM-to-image approximation is implied.

`videoml/ascii-render-pass` uses a static authored-scene snapshot. It retains the owned snapshot handle until disposal and releases it on a failed mount or cancellation. Its luminance summed-area table is additional effect-owned algorithm scratch, bounded by the snapshot dimensions; the provider's bitmap/derived-canvas quota does not account for this table. The temporary source raster is cleared after its pixels are sampled, and the table and output canvas are cleared on disposal.
